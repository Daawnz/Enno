# Enno

A one-click deep focus blocker browser extension with a Zen Garden design.
Supports Chrome and Firefox (Manifest V3, `declarativeNetRequest`).

## What it does

- Enter Focus to start a 90-minute focus session.
- Distraction sites (Reddit, YouTube, Instagram, X, and more) are blocked out of the box, with extras added per browser language.
- The blocked page offers an Override button: a 3-second breathing pause, then a single pass through; refreshing re-blocks.
- The popup includes a theme control: Light (default) or Dark. Choosing Dark overrides the browser theme for the popup and blocked page.
- Everything lives in local browser storage; nothing is transmitted anywhere.

The repo also includes a static landing page (install + blocklist transparency) served from Cloudflare Pages.

## Theme override

The popup has a compact theme control that switches between:

- **Light** – default extension theme.
- **Dark** – force dark extension UI.

The choice is stored locally in `chrome.storage.local` and applied to the popup and blocked page through `data-theme` on `<html>` plus the shared tokens in `app/common/theme.css`. On Chrome the toolbar icon follows the Light/Dark preference; Firefox keeps its native browser-theme toolbar icons.

The theme feature itself requires no new manifest permission beyond `storage`; the old `offscreen` browser-theme watcher was removed with Auto mode.

## Building from source (for Mozilla add-on review)

This extension is built with Vite (bundling and minification), Paraglide (i18n code generation), esbuild (blocklist rules generation), and Tailwind CSS (stylesheet generation).
The add-on itself is neither obfuscated nor hand-minified: the original TypeScript/Svelte sources in `app/` are what must be reviewed.
The steps below reproduce the exact add-on submitted to AMO.

### Prerequisites

- A recent desktop OS: Linux, macOS, or Windows.
- Node.js 22.12 or newer (Vite 8 requirement; 20.19+ also works).
  Install from https://nodejs.org or via your package manager (nvm, apt, brew, winget, ...).
- bun 1.x, used to install dependencies and pin versions.
  Install from https://bun.sh (`curl -fsSL https://bun.sh/install | bash`).
- Git. Install from https://git-scm.com.

### Checkout and configure

```bash
git clone https://github.com/Daawnz/Enno.git
cd Enno
cp .env.example .env
```

`.env.example` contains only public, non-secret configuration (production landing-page URL, GitHub URL).
Copying it to `.env` is required so the generated `manifest.json` matches the production build, notably the `externally_connectable` allowlist.
It is also possible to export the same variables (`VITE_LANDING_URL`, ...) as real environment variables instead.

### Install dependencies

```bash
bun install
```

The committed lockfile `bun.lock` pins every dependency, so installs are reproducible.

### Build

```bash
npm run build
```

This runs the full pipeline:

1. `prebuild` / `i18n:compile` - regenerates the Paraglide i18n modules under `app/common/i18n/generated/` from the message catalogs in `project.inlang/`.
2. `build:extension` - Vite bundles and minifies the extension into `dist/extension/` (Chrome build).
3. `build:landing` - Vite builds the static landing page into `dist/landing/`.
4. `scripts/build-static.mjs` - regenerates `rules.json` and `rules-*.json` from `app/extension/src/core/blocklist.ts`, fills in `manifest.json` from `app/extension/manifest.template.json`, and produces the Firefox build in `dist/extension-firefox/` (Firefox manifest differences are computed by `buildFirefoxManifest()` in that script).

Generated artifacts (`rules.json`, `manifest.json`, `dist/`) are machine-generated at build time and are not committed; they derive deterministically from the committed sources, `.env`, and lockfile.
The Paraglide output under `app/common/i18n/generated/` is committed for editor support but is regenerated by the `prebuild` step on every build.

### Validate

```bash
npm run typecheck
npm run lint
npm run test:unit
npm run test:e2e
```

### Package the Firefox add-on

```bash
cd dist/extension-firefox && zip -r ../enno-firefox.zip . && cd ../..
```

That zip is the add-on file uploaded to AMO, and the unbuilt source (without `node_modules/`, `dist/`, and `.env`) is the source code attached to the submission notes or referenced by the public repository.

## Development

Dependencies are installed with bun (`bun install`); scripts are launched with npm.

```bash
bun install          # install dependencies
npm run build        # build extension + landing, regenerate rules.json/manifest.json
npm run typecheck    # svelte-check + tsc
npm run lint         # eslint
npm run test:unit    # vitest on the pure core
npm run test:e2e     # build + Playwright suite
npm run scan:lhci    # Lighthouse gates on the landing site
npm test             # full pipeline
```

Load the unpacked extension from `dist/extension/` (Chrome: `chrome://extensions` -> Load unpacked) or `dist/extension-firefox/` (Firefox: `about:debugging` -> This Firefox -> Load Temporary Add-on).
The bundle is gitignored; run `npm run build` before loading or running E2E tests.
